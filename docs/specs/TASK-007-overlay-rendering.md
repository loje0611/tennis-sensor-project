**depends_on:** TASK-001, TASK-003, TASK-006

## 1. Overview & Scope
원본 영상 위에 관절 스켈레톤을 그리고, 임팩트 프레임에서 시각 효과(붉은 테두리·`IMPACT!`)와 오토 일시정지·진단 툴팁을 합성해 분석 영상(`mp4v`)을 생성한다. 입력은 `pose_data`(TASK-001), `impact_frames`(TASK-003), `swing_feedbacks`(TASK-006) 계약이다. 합성 입력으로 독립 테스트가 가능하다.

한 임팩트에 **여러 개의 툴팁이 동시에 표시**되므로, 툴팁 배치는 서로 겹치지 않고 화면 안에 들어오는 것이 이 기능의 핵심 품질 속성이다. 본 명세는 배치의 구체적 알고리즘을 지정하지 않고 **만족해야 할 불변식**을 규정한다. 불변식을 만족하는 어떤 배치 전략이든 채택할 수 있다.

## 2. Definitions & References
- **POSE_CONNECTIONS**: MediaPipe 33-point 뼈대 연결쌍 35개를 모듈 상수로 직접 정의(외부 의존성 제거).
- **가시성 임계값**: `visibility > 0.5`.
- **피드백 계약**: `swing_feedbacks[frame]=[{"text": str, "target_joint": int}]` (TASK-006).
  - 한 임팩트 프레임당 피드백은 **1개 이상 3개 이하**이다.
  - `target_joint`로 사용되는 인덱스는 골반 24, 손목 16, 팔꿈치 14, 어깨 12이며, **서로 다른 피드백이 같은 관절을 타겟으로 지정할 수 있다**(예: `Late Wrist`와 `Low Path`가 모두 16).
- **툴팁(tooltip)**: 하나의 피드백을 표시하는 시각 요소 묶음. **타겟 마커**(타겟 관절 위 이중 원), **지시선**(마커 ↔ 박스), **텍스트 박스**(배경 사각형 + 테두리 + 텍스트)로 구성된다.
- **텍스트 박스 사각형**: 박스 배경 사각형이 덮는 픽셀 영역(테두리 포함). 배치 불변식은 이 사각형을 대상으로 판정한다.
- **배너 영역(banner region)**: `IMPACT!` 텍스트가 차지하는 사각형 영역(FR-5).
- **MIN_GAP**: 인접 요소 사이에 확보해야 할 최소 여백. **10 px**.

## 3. Functional Requirements
- **FR-1 (출력 경로)**: 미지정 시 `{video}_analyzed{ext}`.
- **FR-2 (점)**: `vis>0.5` 관절에 반경 4 녹색(0,255,0) 원. 픽셀좌표 `x*width`, `y*height`.
- **FR-3 (선)**: 연결쌍 양끝 `vis>0.5`이면 흰색(255,255,255) 두께 2.
- **FR-4 (결측 스킵)**: 프레임 첫 관절 NaN이면 스켈레톤 생략.
- **FR-5 (임팩트 효과)**: `frame ∈ impact_frames`이면 두께 10 붉은(0,0,255) 테두리 + `IMPACT!`(좌상단, scale 1.5, 두께 4).
- **FR-6 (오토 일시정지)**: 임팩트이고 `swing_feedbacks`에 있으면 정지 프레임 `int(fps*2.5)`회 반복 기록.
- **FR-7 (반투명)**: 정지 프레임에 검정 사각형 `addWeighted(0.5, 0.5)`.
- **FR-8 (툴팁 구성·스타일)**: 정지 프레임에서 각 피드백마다 툴팁 1개를 렌더링한다.
  - 타겟 마커: 타겟 관절 픽셀좌표에 청록(0,255,255) 채움 원(반경 8)과 테두리 원(반경 15, 두께 2).
  - 지시선: 타겟 마커 중심과 해당 텍스트 박스를 잇는 청록 직선(두께 2). **모든 툴팁은 지시선으로 자신의 타겟 마커와 연결되어 식별 가능해야 한다.**
  - 텍스트 박스: 검정(0,0,0) 채움 배경 + 청록(0,255,255) 테두리(두께 2), 텍스트는 청록.
  - 텍스트: `FONT_HERSHEY_SIMPLEX`, 기준 `font_scale = 1.6`, `thickness = 3`.
  - 박스 크기는 실제 렌더링될 텍스트의 측정 크기(`getTextSize`)로부터 산출하며, **텍스트는 박스 안에 완전히 포함**되어야 한다. 고정 폭 상수를 가정하지 않는다.
- **FR-9 (툴팁 배치 불변식)**: 한 정지 프레임에 렌더링된 모든 텍스트 박스 사각형의 집합은 아래를 **모두** 만족해야 한다. 배치 알고리즘은 구현자가 선택한다.
  - **INV-1 (상호 비겹침)**: 서로 다른 두 텍스트 박스 사각형의 교집합 면적은 **0**이며, 두 사각형 사이 간격은 `MIN_GAP` 이상이다.
  - **INV-2 (프레임 내부)**: 모든 텍스트 박스 사각형은 프레임 경계 `[0,width]×[0,height]` 안에 **완전히** 포함된다.
  - **INV-3 (배너 비간섭)**: 어떤 텍스트 박스도 `IMPACT!` 배너 영역과 겹치지 않는다.
  - **INV-4 (근접성)**: 각 텍스트 박스는 불변식 INV-1~3을 깨지 않는 범위에서 자신의 타겟 마커에 가깝게 배치한다. 배치 후보가 여럿이면 타겟 마커에 더 가까운 쪽을 선택한다.
  - **INV-5 (가독 축소 허용)**: 기준 `font_scale = 1.6`으로 INV-1~3을 만족시킬 수 없는 경우에 한해, 해당 프레임의 **모든** 툴팁 텍스트 배율을 동일하게 낮출 수 있다. 하한은 `0.6`이며, 하한에서도 배치가 불가능하면 **초과분 툴팁을 렌더링하지 않는다**(겹쳐 그리는 것보다 생략이 우선한다).
  - **INV-6 (결정성)**: 동일한 입력에 대해 배치 결과는 항상 동일해야 한다(무작위성 금지).
- **FR-10 (writer)**: `VideoWriter_fourcc(*'mp4v')`, 원본 fps/해상도.

## 4. Interfaces & Data Structures
```python
def render_overlay(video_path, pose_data, impact_frames=None,
                   swing_feedbacks=None, output_path=None) -> str | None
```
- 반환: 저장 경로, 실패 시 `None`. H.264(libx264) 변환은 app 계층(TASK-008)이 moviepy로 수행.
- 배치 계산을 보조 함수로 분리하는 것을 권장한다. 분리할 경우 그 함수는 영상 I/O 없이 **텍스트 목록·타겟 좌표·프레임 크기만으로 박스 사각형 목록을 반환**하여 단위 테스트가 가능해야 한다.

## 5. UI/UX Requirements
- 영상 합성 요소의 시각 스펙은 §3에 정의. 웹 배치는 TASK-008.
- 사용자 보고(원문): "분석 결과 영상에서 임팩트 시 문제점을 보여주는 tooltip 이 겹쳐서 보이는 경우가 발생하고 있어". 툴팁이 서로 겹쳐 판독 불가능해지는 상태는 결함으로 간주한다.

## 6. Non-Functional Requirements
- 의존성: `opencv-python`, `numpy`.
- 배치 계산은 프레임당 피드백 최대 3개 기준으로 렌더링 시간에 유의미한 영향을 주지 않아야 한다.

## 7. Error Handling & Edge Cases
- **EH-1**: 영상 부재/열기 실패 → `None`.
- **EH-2**: `pose_data` 길이 부족 → 초과 프레임 스켈레톤 생략.
- **EH-3**: 타겟 관절 NaN → 해당 툴팁만 스킵. 나머지 툴팁은 정상 렌더링되고, 정지 프레임 반복은 그대로 수행된다.
- **EH-4 (다중 피드백)**: 한 프레임에 피드백이 2~3개인 경우에도 FR-9 불변식이 유지되어야 한다.
- **EH-5 (타겟 밀집)**: 여러 타겟 관절이 서로 근접하거나 동일 좌표인 경우에도 텍스트 박스는 겹치지 않아야 한다.
- **EH-6 (프레임 경계)**: 타겟 관절이 프레임 가장자리(상/하/좌/우)에 있어 관절 옆에 박스를 놓을 수 없는 경우, 박스를 프레임 안쪽으로 옮겨 INV-2를 지킨다.
- **EH-7 (소형 해상도)**: 프레임 폭이 좁아 기준 배율의 텍스트가 들어가지 않는 경우 INV-5의 축소·생략 규칙을 적용한다. 박스가 프레임 밖으로 나가는 결과는 허용되지 않는다.

## 8. Acceptance Criteria
- [ ] `vis>0.5` 관절(녹색)·뼈대(흰색)가 그려진다.
- [ ] 임팩트에 붉은 테두리·`IMPACT!`가 출력된다.
- [ ] 임팩트에서 `fps*2.5`회 정지 프레임이 반복된다.
- [ ] 정지 프레임에 반투명(0.5) 오버레이가 적용된다.
- [ ] 툴팁이 청록 타겟 마커·지시선·검정 배경 박스로 렌더링되고, 각 박스가 지시선으로 자신의 타겟 마커와 연결된다.
- [ ] **피드백이 3개인 임팩트 프레임에서, 텍스트 박스 사각형들의 쌍별 교집합 면적이 0이다.**
- [ ] **타겟 관절이 프레임 하단·상단 경계에 밀집한 경우에도 텍스트 박스 쌍별 교집합 면적이 0이다.**
- [ ] **모든 텍스트 박스가 프레임 경계 내부에 완전히 포함된다(좌표 음수 또는 `width`/`height` 초과 없음).**
- [ ] **어떤 텍스트 박스도 `IMPACT!` 배너 영역과 겹치지 않는다.**
- [ ] **720p·1080p·소형(예: 640×480) 해상도 각각에서 위 비겹침·프레임 내부 속성이 유지된다.**
- [ ] **동일 입력을 두 번 렌더링하면 동일한 박스 배치가 산출된다.**
- [ ] 타겟 관절이 NaN인 피드백은 툴팁이 생략되고, 나머지 툴팁과 정지 프레임 반복은 정상 동작한다.
- [ ] 영상 부재 시 `None`을 반환한다.
- [ ] 합성 입력(pose_data/impact_frames/swing_feedbacks)만으로 테스트가 통과한다.

> **검증 방식 제약**: 위 기준은 **렌더링 결과(박스 사각형 좌표 또는 출력 프레임 픽셀)** 로 검증해야 한다. 소스 파일 내용을 문자열로 대조하는 방식(예: 특정 상수 리터럴 존재 여부 확인)은 유효한 검증으로 인정하지 않는다.
