## 🔍 분석

### 1. 480p: ✅ 실시간 처리 가능 (29.9 fps)

- **30fps 목표를 사실상 달성** (29.9 fps ≈ 30 fps)
- 평균 지연 39.6ms, P95도 54ms로 매우 안정적
- **Confidence 0.989**: 랜드마크가 높은 신뢰도로 검출됨
- 이 해상도에서는 **실시간 스윙 분석이 충분히 가능**

### 2. 720p / 1080p: ⚠️ 실시간 부적합 (12~13 fps)

- 두 해상도 모두 약 **13fps** 수준으로 30fps 목표 대비 절반 이하
- 평균 지연 ~150ms로 임팩트 순간을 놓칠 수 있음
- **Confidence 0.000**: 포즈가 검출되지 않음 (poses=0)
  - 이는 해상도 전환 시 카메라가 사람을 향하지 않았거나, 높은 해상도에서 처리 지연으로 프레임이 드롭되면서 랜드마크 추출 자체가 실패한 것으로 추정

> **참고**: 720p/1080p에서 confidence=0.000은 해상도의 정확도 문제가 아니라 벤치마크 환경 문제일 가능성이 높습니다. 480p에서 0.989로 정상 검출되었으므로, 모델 자체는 정상 동작합니다. 다만 13fps라는 처리 속도 자체가 실시간 분석에는 부적합합니다.

## 🏆 결론 및 C그룹 설계 권고

### 결론: **480p 해상도로 실시간 포즈 분석이 가능하다**

| 판정 항목 | 결과 | 평가 |
|---|---|---|
| 30fps 실시간 처리 | 480p에서 **29.9 fps** 달성 | ✅ **PASS** |
| 프레임당 지연 | 480p 평균 **39.6ms** (P95: 54ms) | ✅ **PASS** |
| 랜드마크 검출 정확도 | 480p confidence **0.989** | ✅ **PASS** |
| 720p/1080p 실시간 | 약 **13 fps** | ❌ **FAIL** |

### C그룹 설계 권고사항

1. **`:feature:lab`의 카메라 해상도는 480p(640×480)로 고정**
   - 30fps 실시간 처리가 가능하고, Confidence도 0.989로 충분
   - 720p 이상은 FPS 반토막으로 실시간 분석 불가

2. **GPU Delegate 적용 시 720p도 가능성 있음**
   - 이번 테스트는 CPU 기본값으로 수행됨
   - GPU Delegate 적용 시 720p에서도 25~30fps 달성 가능성 존재 (추후 검증 가능)

3. **PHASE2_PLAN.md의 대안 전략은 불필요**
   - 480p에서 30fps가 나오므로, "임팩트 ±2초 구간만 처리" 등의 타협안은 당분간 필요 없음
   - 다만 배터리 소모 테스트는 별도로 필요 (이번 스파이크 범위 외)

4. **B그룹 포팅 결과와의 호환성**
   - `:core:vision` 모듈의 `PoseFrame` 데이터 계약은 정규화된 [0,1] 좌표 기반이므로 해상도에 무관
   - 480p에서 추출한 랜드마크도 동일한 정규화 좌표로 제공되어 알고리즘 정확도에 영향 없음
